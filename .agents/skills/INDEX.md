# Playbook skills, v2

Read this and the project's `PROJECT.md` at the start of every session, then the `core` skill. Load any other skill only when its work starts, and only if `PROJECT.md` lists it.

- **core** (all): rules for every session, backed by command and secret guards. Load at start, always.
- **crew** (all): jobs and the skills each loads, fresh sessions per feature, board, handoffs, night shift. Load when starting, splitting, handing off or escalating work.
- **planning** (all): the plan page in the one plan look, screens as pictures, and `checks.md`. Load when an idea becomes a plan.
- **testing** (all): what to test, honest and reliable tests, running them. Load before writing, reviewing or fixing any test.
- **code-standards** (all): shaping code and reviewing it. Load before writing or reviewing code.
- **checkpoint** (all): Ready to ship, the builder's what-to-try list on staging and James's approval. Load when a feature is merged and working on staging.
- **shipping** (all): branches, pinned merges, guarded promotion and what "live" means. Load before merging, deploying or saying "live".
- **stack-guide** (all): default tools and when to choose otherwise. Load when planning or adding a dependency.
- **access** (apps, websites): just James, public, team or sign-up, as a setting. Load when planning or building anything with a web address.
- **accessibility** (apps, websites): the WCAG 2.2 AA floor and the checkpoint items. Load before building or reviewing screens or emails.
- **design-slot** (apps, websites, in `DESIGN-SLOT.md`): what a design skill provides, and the look before one exists. Load when building any screen, or writing a design skill.
- **playbook** (all): how the playbook is kept, budgets, and turning lessons into changes. Load when proposing a rule, running a retro or editing a skill.
